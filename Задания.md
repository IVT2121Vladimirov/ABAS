# Практика

### Этап 0: Подготовка и создание автоматизированной системы (АС)



#### Цель: 

Развернуть и настроить тестовую АС, которая будет объектом анализа.



#### Задачи:



* Развернуть виртуальную инфраструктуру согласно схеме.
* Установить и настроить операционные системы на серверах и рабочих станциях.
* Настроить базовые сетевые службы (DNS, AD, файловый обмен, веб-сервис).
* Сознательно внести в систему ряд уязвимостей (устаревшее ПО, слабые пароли, открытые порты, небезопасные настройки веб-приложения).



### Этап 1: Организация работ и согласование границ (в соответствии с Разделом 2 Методики)



#### Цель: 

Оформить документы, регламентирующие проведение анализа.



Задачи:



* Составить условный «Приказ» или «Техническое задание» на проведение анализа уязвимостей (определить заказчика, исполнителя, сроки).
* Определить и задокументировать границы проведения работ (п. 2.13-2.15): составить список IP-адресов, доменных имен, конкретных серверов и рабочих станций, подлежащих проверке.
* Определить виды анализа: С1 (внешнее сканирование) и С2 (внутреннее сканирование) с привилегиями администратора и без аутентификации (п. 2.10-2.11).



### Этап 2: Настройка сетевого оборудования периметра и защитных механизмов



#### Часть 2.1: 

Настройка межсетевого экрана и системы защиты (UserGate/«Код безопасности»)



* Настроить правила фильтрации трафика (разрешить только необходимые порты для веб-сервера, RDP/SSH для управления).
* Настроить систему обнаружения вторжений (IDS) или учет событий безопасности.



#### Часть 2.2: 

Настройка активного сетевого оборудования (Cisco/MikroTik)



* Настроить VLAN для сегментации внутренней сети (серверный сегмент, сегмент пользователей).
* Настроить Access Control Lists (ACL) для ограничения доступа между сегментами.
* Настроить безопасные протоколы управления (SNMPv3, SSH вместо Telnet).



### Этап 3: Сбор исходной информации об АС (Соответствует п. 3.1 Методики, Таблица 1)



#### Цель: 

Провести инвентаризацию АС.



#### Задачи (ИНП – для внешнего, ИВИ – для внутреннего анализа):



* ИНП.1-ИНП.4: С использованием Nmap и поисковых сервисов определить публичные IP, доменные имена, открытые порты и службы на периметре.
* ИНП.5-ИНП.7: Определить версии ПО (например, веб-сервера) доступные извне.
* ИВИ.1-ИВИ.5: Изнутри сети провести сканирование для построения полной сетевой карты, инвентаризации всех узлов, ОС, сетевых служб.
* ИВИ.6: Собрать информацию о пользователях и политиках домена.
* ИНП.10 / ИВИ.8: Выявить неиспользуемые или несанкционированные сетевые ресурсы.



#### Результат: 

Подробный отчет по инвентаризации для согласования с «заказчиком».



### Этап 4: Внешний анализ уязвимостей (С1) (Соответствует п. 3.2 Методики, Таблица 2)



#### Цель: 

Выявить уязвимости, доступные из сети «Интернет».



#### Задачи (Проводятся из внешней сети):



* СИН.1-СИН.8: Сканирование периметра (МЭ, открытые порты) на наличие уязвимостей в конфигурации (небезопасные протоколы, управление доступом).
* ВЕБ.1.1-ВЕБ.1.9: Углубленный анализ веб-приложения на типовые уязвимости OWASP Top 10 (SQL-инъекции, XSS, небезопасная десериализация и т.д.) с помощью сканеров и ручной проверки (например, Burp Suite).
* СУД.1: Проверка служб удаленного доступа (если таковые открыты).



#### Результат: 

Отчет внешнего сканирования с перечнем уязвимостей.



### Этап 5: Внутренний анализ уязвимостей (С2) (Соответствует п. 3.3 Методики, Таблица 3)



#### Цель: 

Выявить уязвимости внутри защищенного периметра.



#### Задачи (Проводятся изнутри сети, с учетной записью администратора и без):



* ОПС.1.1-ОПС.1.15: Проверка конфигурации ОС на рабочих станциях и серверах (слабые пароли, избыточные права, невыключенные службы, настройки аудита).
* ДИС.1.1-ДИС.1.3: Анализ безопасности доменной инфраструктуры (политики паролей, делегирование прав, устаревшие протоколы аутентификации).
* СУБД.1.1-СУБД.1.16: Проверка настроек СУБД (если используется).
* УСИ.1-УСИ.8: Проверка конфигурации внутреннего сетевого оборудования.
* Сканирование внутренних IP-адресов с помощью сканера уязвимостей для выявления известных уязвимостей ПО.



#### Результат: 

Отчет внутреннего сканирования с перечнем уязвимостей.



### Этап 6: Оценка выявленных уязвимостей (Соответствует п. 3.4 Методики)



#### Цель: 

Определить критичность уязвимостей и необходимость их устранения.



#### Задачи:



* Классифицировать все найденные уязвимости по уровню опасности (критический, высокий, средний, низкий). Использовать CVSS и/или БДУ ФСТЭК.
* Провести экспертную оценку для уязвимостей среднего и низкого уровня: могут ли они быть использованы в связке для реализации угроз из модели угроз? (Например, уязвимость низкого уровня на рабочей станции + недостаток сетевой сегментации = переход нарушителя к серверам).
* Сформировать сводную таблицу с рекомендациями по устранению для каждой критичной/высокой и выбранной средней/низкой уязвимости.
* Сформулировать предварительный вывод о соответствии/несоответствии АС требованиям.



### Этап 7: Составление итогового отчета (Соответствует Разделу 4 Методики)



#### Цель: 

Оформить итоговый документ по результатам анализа.



#### Структура отчета (Протокола):



* Основание, цели, границы проведения работ.
* Описание АС и использованных средств анализа.
* Результаты инвентаризации (из Этапа 3).
* Результаты внешнего (Этап 4) и внутреннего (Этап 5) анализа.
* Оценка уязвимостей с обоснованием критичности (Этап 6).
* Рекомендации по устранению (с указанием приоритета).
* Приложения: Скриншоты, логи сканирования, выводы инструментов.



### Этап 8: Защита работы



Студенты представляют итоговый отчет и защищают его перед «комиссией» (преподаватель и другие студенты в роли представителей заказчика), объясняя методику, найденные проблемы и предлагаемые меры защиты.

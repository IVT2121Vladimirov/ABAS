# Анализа защищенности ИС

 

Сбор исходной информации (инвентаризация)

Сформировать точную, полную и актуальную модель тестируемой информационной системы — "цифровой двойник" в контексте безопасности.



Нормативная база: Что требует методика ФСТЭК?

Согласно разделу 3.1 методики, на этапе сбора исходной информации исполнитель должен получить:



Обязательные данные:



* Состав, наименования и версии программных и программно-аппаратных средств
* Сетевая инфраструктура и сегменты ИС
* Информация о пользователях ИС
* Иная информация, необходимая для проведения анализа



Юридический аспект: Этот этап проводится на основании договора или приказа. Заказчик обязан предоставить доступ и информацию, но если информации нет — исполнитель проводит инвентаризацию самостоятельно с последующим согласованием перечня объектов с заказчиком.

Два направления инвентаризации: Периметр и внутренняя инфраструктура



### Инвентаризация периметра (ИНП)

Цель: Определить все, что "смотрит" в интернет и доступно внешнему злоумышленнику.



Работы согласно таблице 1 методики:



Код работы	Содержание работы	Важность


| Код работы | Содержание работы | Важность / Цель выполнения |
| :--- | :--- | :--- |
| **ИНП.1** | Определение внешних IP-адресов | Формирование базового перечня целей для внешнего тестирования (С1). |
| **ИНП.2** | Определение доменных имен | DNS-разведка, поиск субдоменов, связанных с организацией. |
| **ИНП.3** | Определение веб-ресурсов | Выявление всех точек входа веб-приложений (основных сайтов, панелей управления, API). |
| **ИНП.4** | Поиск внешних интерфейсов и открытых портов | Обнаружение сетевых служб (SMTP, RDP, SSH, FTP и др.), доступных извне. |
| **ИНП.5** | Сбор информации о сетевых службах и сервисах | Детализация обнаруженных служб (почта, удаленный доступ, файлообмен). |
| **ИНП.6** | Сбор информации о версиях ПО | Фингерпринтинг, определение технологического стека (ОС, веб-сервер, СУБД) для поиска известных уязвимостей. |
| **ИНП.7** | Определение конфигураций | Аналих начальных настроек доступных служб на предмет стандартных или небезопасных конфигураций. |
| **ИНП.8** | Сбор информации об аутентификации | Изучение механизмов входа (логин/пароль, сертификаты), наличие MFA. |
| **ИНП.9** | Сбор информации о моделях ИИ (машинного обучения) | **Ключевое нововведение 2025 г.!** Выявление компонентов с ИИ для последующего анализа на специфические уязвимости (инжекция промптов, утечка данных обучения). |
| **ИНП.10** | Выявление неиспользуемых/неидентифицированных объектов | "Уборка" периметра. Нахождение "забытых" IP, доменов или сервисов, представляющих неучтенный риск. |
| **ИНП.11** | Выявление несанкционированных точек подключения | Поиск "теневого IT" на периметре (несанкционированные облачные сервисы, устройства, VPN-шлюзы). |




### Методы сбора информации для периметра:



#### Инвентаризация внутренней инфраструктуры (ИВИ)



Цель: Построить полную карту внутренней сети и всех ее компонентов.



Работы согласно таблице 1 методики:



Код работы	Содержание работы				Особенность

| Код работы | Содержание работы | Важность / Цель выполнения |
| :--- | :--- | :--- |
| **ИВИ.1** | Сбор информации об архитектуре внутренней сети | Построение детальной сетевой карты (топологии), включая сегменты (VLAN), IP-подсети, маршрутизацию. База для планирования внутреннего сканирования (С2). |
| **ИВИ.2** | Сбор информации о внутренних сетевых службах | Обнаружение и каталогизация всех активных сервисов (файловые шары, внутренние порталы, службы каталогов, базы данных, сервисы мониторинга). |
| **ИВИ.3** | Инвентаризация серверов и систем хранения | Учет всех физических и виртуальных серверов, систем управления базами данных (СУБД), файловых хранилищ, почтовых серверов. Определение их ролей и ответственных. |
| **ИВИ.4** | Инвентаризация АРМ пользователей | Учет типов рабочих устройств (ПК, ноутбуки, тонкие клиенты), версий ОС, критического установленного ПО. Определение типовой и отклоняющейся конфигурации. |
| **ИВИ.5** | Инвентаризация прикладного ПО | Выявление и учет всего бизнес-ПО: веб-серверы, системы электронного документооборота (СЭД), CRM/ERP, мобильные приложения, специализированное ПО. |
| **ИВИ.6** | Сбор информации о пользователях и политиках | Анализ доменной структуры: учетные записи (в т.ч. привилегированные), группы, политики паролей, настройки блокировки, наличие MFA. Ключевой этап для оценки рисков инсайдеров. |
| **ИВИ.7** | Определение конфигураций внутренних систем | Углубленный анализ настроек обнаруженных систем (серверов, служб, ПО) на предмет отклонений от безопасных базовых конфигураций. |
| **ИВИ.8** | Выявление неиспользуемых объектов внутри сети | Обнаружение "мертвых" IP-адресов, неиспользуемых сервисов, устаревших серверов или АРМ. Оптимизация инфраструктуры и снижение поверхности атаки. |
| **ИВИ.9** | Выявление несанкционированных подключений | Поиск внутреннего "теневого IT": неучтенных устройств (смартфоны, Raspberry Pi), несанкционированных точек доступа, нелегального ПО или сервисов в корпоративной сети. |



#### Методы сбора информации для внутренней инфраструктуры:



* Автоматизированное сканирование сети (с согласования заказчика)
* Анализ существующих систем мониторинга (SIEM, системы управления)
* Изучение документации (схемы сети, реестры активов)
* Опрос администраторов и ответственных лиц



### Практические инструменты и техники



#### Для внешней инвентаризации:

Nmap (-sS, -sV, -O, --script) 

Amass, Sublist3r (поиск субдоменов)

Shodan, Censys (поиск в интернет-базах)

theHarvester (сбор emails, имен)



#### Для внутренней инвентаризации:


Active Directory PowerShell модули

Средства сетевого обнаружения (Advanced IP Scanner)

Инвентаризационные агенты (если уже установлены)

Анализ DHCP и DNS логов

### Особое внимание! Новые требования 2025 года:

* Модели машинного обучения (ИНП.9, МИИ) — теперь необходимо инвентаризировать системы ИИ
* Средства контейнеризации (СКО) — Docker, Kubernetes кластеры
* Программируемые логические контроллеры и "умные" устройства — IoT в промышленных системах





После успешного проведения инвентаризации формируются исходные данные (п. 3.1.6 методики):



* Состав и версии всего ПО (системное, прикладное, СЗИ)
* Информация об актуальности обновлений
* Архитектура (карта) сети с IP-адресами и доменными именами
* Способы идентификации и аутентификации
* Сведения о типовых конфигурациях



Ключевой документ: Согласованный с заказчиком перечень объектов тестирования, который становится основой для всех последующих этапов анализа.



Сбор исходной информации — это не техническая рутина, а интеллектуальная работа по построению модели безопасности.



Принципы успешной инвентаризации:



* Полнота — знать все компоненты ИС
* Точность — иметь корректные данные о версиях и конфигурациях
* Актуальность — информация должна соответствовать текущему состоянию
* Структурированность — данные должны быть удобны для анализа на следующих этапах
